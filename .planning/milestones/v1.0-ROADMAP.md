# Milestone v1.0: MVP

**Status:** ✅ SHIPPED 2026-05-30
**Phases:** 1–4
**Total Plans:** 14

## Overview

This milestone hardened AutoMux from a working prototype into a reliable, user-friendly tool. Four active phases addressed the root causes of user-visible failures — a broken permissions loop, unsafe panic paths, a misleading README, and UX dead-ends for key binding and process targeting — then locked in CI hygiene before shipping. Phase 5 was reserved for auto-updater infrastructure and scoped to v2.

## Milestone Summary

**Key Decisions:**

- Reserve auto-updater as Phase 5 (v2) — core reliability must be solid first; signing/entitlements required as prerequisite
- MacPlatformObserver stored via app.manage() to guarantee it lives for the full application lifetime
- Key capture widget captures DOM key events and maps to native codes via keymap.ts — no raw integers exposed to users
- Process picker uses list_running_apps IPC backed by NSWorkspace (macOS) and EnumProcesses (Windows)
- SHA pinning for third-party GitHub Actions uses full 40-char commit SHAs with inline tag annotations for auditability

**Issues Resolved:**

- macOS false-positive "security denied" after accessibility permission grant — fixed via 3s frontend poll
- CGEventTap silently disabled after OS timeout — fixed via inline TapDisabledByTimeout detection and re-enable
- Windows held inputs remaining stuck after Ctrl+Shift+Q — fixed via synchronous flush before process::exit
- 5 production unwrap()/expect() panics on input injection hot path — eliminated
- MacPlatformObserver observer token dropped at end of setup function — fixed via app.manage()
- Raw CGKeyCode/VK integers shown in UI — replaced with human-readable key names via keymap.ts
- Manual process-name text field — replaced with running-process picker on both platforms
- CI used floating `@v0` / `@v4` action tags — pinned to full SHA
- macOS CI produced arm64-only binary — fixed with `--target universal-apple-darwin` + lipo verification

**Technical Debt Incurred:**

- RELY-01 partial: accessibility poll does not call initialize_tap() on passive grant detection (direct System Settings grant without clicking "Request Access" requires app restart)
- CR-01 (Phase 1): flush_held_inputs holds REGISTRY lock while posting CGEvents — potential deadlock on macOS emergency stop
- CR-01 (Phase 3 Windows): OpenProcess HANDLE in list_running_apps_impl never closed via CloseHandle
- CI: npm install used instead of npm ci in release.yml; binary discovery pattern fragile
- auto-save-error Tauri event emitted but App.tsx has no listener — user gets no feedback on silent auto-save failure

See `.planning/milestones/v1.0-MILESTONE-AUDIT.md` for full tech debt inventory.
