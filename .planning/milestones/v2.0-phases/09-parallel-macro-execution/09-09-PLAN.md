<objective>
Close the two Blocker-severity gaps recorded in 09-VERIFICATION.md (truths #10 and #11), both rooted in the same IPC argument-casing defect (CR-01/CR-02 in 09-REVIEW.md):

1. Editing an existing macro's **target app** via the card-edit dropdown silently no-ops — `set_macro_target_app(id, target_app: Option<String>)` has no rename_all attribute, so Tauri looks up the camelCase key `targetApp` while the frontend sends `target_app`; a missing key on an `Option<T>` param silently resolves to `None`, discarding the user's selection.
2. Editing an existing macro's **hotkey** via the card-edit UI hard-fails on macOS every time — `bind_hotkey(macro_id: Uuid)` / `unbind_hotkey(macro_id: Uuid)` are non-`Option` params, so a missing `macroId` key is a hard `Err`; `unbind_hotkey` throws on the first line of `handleCardSetTriggerKey`, and the catch block then mislabels the failure as a hotkey-conflict toast.

The fix is a single consistent direction — add `#[command(rename_all = "snake_case")]` to the backend commands — chosen because the frontend already sends the Rust snake_case parameter names verbatim everywhere (single-word params like `id`/`enabled`/`keycode` work only because camelCase == snake_case for one word). This makes the backend look up the keys the frontend already sends, matching the majority behavior instead of introducing a second convention. The sweep covers ALL affected commands (the two named gaps, the sibling `set_macro_trigger_key`, and the latent-but-currently-unused `update_step_interval`) so no instance of this exact bug is left behind.

This gap-closure round implements no new `## Decisions` items — CONTEXT.md's D-01..D-14 were delivered across plans 09-01..09-08. It restores end-to-end reliability of the app-targeting behavior specified in **D-01** (a macro's `target_app` must actually gate firing) for the *edit* path, which the target-app-persistence fix directly unblocks.

Purpose: A macro that was set up must fire reliably — and must be *editable* reliably. Target-app and hotkey edits currently report success while silently discarding the user's change; this restores the round-trip.
Output: Modified src-tauri/src/ipc/mod.rs (5 rename_all attributes) and src/App.tsx (catch-block error-classification fix).
</objective>
