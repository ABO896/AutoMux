## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| macOS TCC → `check_input_monitoring` probe | The CGEventTap ListenOnly probe reads the live TCC verdict; the probe is scoped to the function and never sets TAP_INITIALIZED |
| Frontend → `check_input_monitoring` / `get_tcc_identity_status` IPC | Untrusted IPC callers; commands return a bool and never accept arguments, so no input validation surface |
| Disk → `tcc_granted_flag_path` | The flag file lives in `app_data_dir()` which is platform-sandboxed by Tauri (V5 Input Validation) |
| App startup → first Accessibility grant | The flag is written on every successful grant, not just the first; this is intentional idempotent behavior, not a security boundary |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-07-06 | Elevation of Privilege | `tcc_granted_flag_exists` could be tampered with to fake an identity change | accept | The flag is advisory only — worst case is the user sees a misleading "AutoMux was updated" subtitle; no security boundary is crossed. RESEARCH §Security Domain calls this out explicitly |
