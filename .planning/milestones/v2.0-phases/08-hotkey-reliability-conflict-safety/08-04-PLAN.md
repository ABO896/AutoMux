<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DOM KeyboardEvent → `computeModifiers` | The browser gives us boolean `e.shiftKey` etc.; the helper maps them to platform-native bit values. The mapping must stay in lockstep with the backend unit tests. |
| Frontend IPC call → Rust StateActor | The frontend sends `(keycode, modifiers)`; the StateActor validates and returns either `Ok(())` or `Err(msg)`. The error string parsing in `showConflictError` must not crash on unexpected shapes. |
| `startCapture` global listener → JSX render | The capture listener is attached to `document` with capture phase; the modifier signal it sets is read by the C-5 chip (Plan 08-05). A race between listener teardown and signal reset can leave a stale `recordingModifiers` value visible. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|----------------|
| T-08-20 | Tampering | `computeModifiers` returns the wrong bits | mitigate | The bit values are pinned by Rust unit tests in Plan 08-01 (CGEventFlag* and MOD_*). Any frontend drift will fail the round-trip on the first device test (Plan 08-06). The bit definitions are also documented inline in the function's JSDoc. |
| T-08-21 | Elevation of Privilege | `showConflictError` parses the error string | accept | The parsing extracts the conflicting macro's name from the backend's well-known error format. If parsing fails, a generic message is shown — the user is not blocked. The macroName field is display-only; it is not used for any subsequent IPC call. |
| T-08-22 | Information Disclosure | The conflict error reveals another macro's name | accept | By design per UX-11. The user must know which macro to unbind. The frontend already has access to all macro names via `state().macros`; the error string is not a new disclosure. |
| T-08-23 | Denial of Service | `setConflictError` timer accumulates | mitigate | The 8-second auto-dismiss timer is single-slot: when a new conflict arrives, the timer is replaced. The signal pattern matches the existing `showProfileMsg` at `App.tsx:415-418` (3-second toast) — both use a single global `setTimeout` per session. |
| T-08-24 | Repudiation | Bare-modifier bindings silently accepted | accept | Per Open Question #1 in RESEARCH.md, modifier-only binds are now allowed (the filter is removed). The `e.code` lookup at line 359 still rejects unmapped codes — a "just Shift" press resolves to CGKeyCode 56 (macOS) or VK 0x10 (Windows), which are in the `*_TO_NAME` tables (`keymap.ts:96, 167`). The user sees "Shift" in the chip and commits. No silent failure mode. |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | No new npm packages. `npx tsc` is the standard compiler, already required by the project. slopcheck gate not relevant. |
</threat_model>
