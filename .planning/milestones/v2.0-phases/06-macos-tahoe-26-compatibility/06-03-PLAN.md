<objective>
Fix the use-after-free crash in the CGEventTap re-enable callback on macOS 26 Tahoe ARM64e, and confirm via on-device test that a macro enabled through the UI toggle actually fires input events. Phase 6 plans 06-01 and 06-02 shipped the live CGEventTap probe and DMG verification, but the on-device session revealed two regressions blocking the COMPAT-01 / COMPAT-03 success criteria: an `EXC_BAD_ACCESS (SIGSEGV)` in `objc_retain + 16` triggered when `TapDisabledByTimeout` fires near tap teardown, and a "macros never fire" symptom likely caused by that crash terminating the tap thread before the StateActor's injection can be observed.

Purpose: Restore COMPAT-01 (macros fire on Tahoe 26) and COMPAT-03 (no crash) — both phase success criteria currently violated. Without this fix, AutoMux is unusable on macOS 26.

Output: A patched `observer.rs` that re-arms the tap via a CFRunLoop-driven restart instead of a per-event spawned thread that captures a raw `CFMachPortRef` as `usize`. No new dependencies, no UI changes, no Windows changes.
</objective>

    - After teardown, `TAP_INITIALIZED == false` and `TAP_STARTING == false`, so the next 3s `check_accessibility` poll in `src-tauri/src/ipc/mod.rs:193` calls `initialize_tap()` again and the tap rearms.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CGEventTap callback thread → CFRunLoop owning thread | Tap callback runs on a CF-managed thread; previously spawned a std::thread that touched a CF object owned by the run loop thread |
| OS (CGEvent service) → AutoMux process | OS delivers `TapDisabledByTimeout` / `TapDisabledByUserInput` events; AutoMux must respond without UB |
| User Accessibility grant → tap arming | The 3s `check_accessibility` poll is the sole reinit trigger after Option B teardown |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Tampering (memory safety) | `observer.rs` TapDisabled callback path | mitigate | Remove `tap.mach_port.as_concrete_TypeRef() as usize` storage and per-event `std::thread::spawn`. Replace with `CFRunLoop::get_current().stop()` so the tap drops on its owning thread (Task 2). |
| T-06-03-02 | Denial of Service (tap stays disabled) | `TAP_INITIALIZED` / `TAP_STARTING` guard pair | mitigate | Reset INITIALIZED then STARTING in the TapDisabled branch (STARTING last per safety-officer invariant) so the existing 3s `check_accessibility` poll in `ipc/mod.rs` reinitializes the tap. Restart gap bounded ≤ 3s (Task 2). |
| T-06-03-03 | Tampering (race on guards) | `TAP_STARTING` flag during TapDisabled teardown | mitigate | Use Release ordering for both stores and clear STARTING strictly after INITIALIZED. Document in code comment that STARTING is the in-flight spawn guard release point (Task 2 + Task 3). |
