<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Manual verification on macOS 26 Tahoe device</name>
  <what-built>
    Plan 06-01 replaced AXIsProcessTrusted() with a live CGEventTap probe in check_accessibility_permissions(false). This fixes the stale per-process TCC cache regression on macOS 15 Sequoia and 26 Tahoe where the function returned false even after the user granted Accessibility. Plan 06-02 Task 1 built a release DMG with this fix included, plus NSAccessibilityUsageDescription in Info.plist.
  </what-built>
  <how-to-verify>
    Install and run the DMG from Task 1 on your macOS 26 Tahoe device. Walk through each scenario:

    **SCENARIO A — COMPAT-02: Permissions detection after fresh grant**
    1. If AutoMux is listed in System Settings → Privacy & Security → Accessibility, remove it first (click the minus button).
    2. Launch AutoMux from the installed .app.
    3. The app should show the Accessibility permission as "not granted" on first launch.
    4. Click "Request Access" — the macOS prompt or System Settings should open.
    5. Grant Accessibility permission in System Settings.
    6. Switch back to AutoMux. Within 3 seconds (the polling interval), the permission indicator should update to "granted" — no app restart needed.
    Expected: permission shows "granted" within ~3s. If it stays "not granted", the live probe fix did not work.

    **SCENARIO B — COMPAT-01: Macros fire after permission is granted**
    1. With Accessibility granted (from Scenario A), create or enable a macro (e.g., a mouse click or key press macro).
    2. Enable the macro and trigger it.
    Expected: the click or key press fires in the target application. If no action fires, CGEventTap failed to arm.

    **SCENARIO C — COMPAT-03: Clean launch, no errors**
    1. Check the macOS Console.app for any crash reports or error messages from AutoMux at launch time.
    2. Specifically look for: "com.alvaro.automux" crash reports, "entitlement" errors, "CGEventTap" failure messages.
    Expected: no crash, no entitlement error, no framework exception. App launches to a working UI.

    **SCENARIO D — App appears in Accessibility Settings list**
    1. Open System Settings → Privacy & Security → Accessibility.
    2. Find AutoMux in the list.
    Expected: AutoMux appears with its name and the usage description "AutoMux requires Accessibility access to monitor and inject keyboard and mouse events for macro automation." (the NSAccessibilityUsageDescription value). If the app does not appear in the list, granting permission is impossible — this is an escalation signal.

    Record pass/fail for each scenario. If all four pass, type "approved". If any fail, describe which scenario failed and what you observed.
  </how-to-verify>
  <resume-signal>
    Type "approved" if all four scenarios pass.
    Or describe the failure: which scenario, what was observed, and whether the app appeared in the Accessibility list.

    Escalation path if CGEventTap::new() fails even after confirmed Accessibility grant (Scenario B fails with probe returning true but macros still don't fire): this is the D-09 trigger — unsigned apps may be hard-blocked on this Tahoe 26 build. Report this as a v3 blocker (requires signing + notarization infrastructure).
  </resume-signal>
