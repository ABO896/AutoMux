<objective>
Wire end-to-end auto-save into the StateActor so macro mutations persist to the `default` profile on disk without user action, while suppressing per-macro writes during profile-load batches (RELY-04, D-05 through D-07).

Purpose: Today, every macro change made during a session is lost unless the user manually clicks Save in the Profiles tab. The README and `persistence.rs` header already claim auto-save behavior. This plan closes that gap by injecting `Arc<ProfileManager>` into `StateActor`, adding a `loading_profile` suppression flag and an `Intent::LoadProfile(String)` variant, calling `auto_save_default().await` after every mutating intent, surfacing failures via a Tauri event, and converting the existing startup restoration (and the IPC `load_profile` command) to use the new bracketed load path so startup does not generate N disk writes.

Output: One vertical slice that lets a user close AutoMux without manually saving and reopen with all their changes intact — backed by a single intent-driven save path that the existing IPC and platform layers already feed.

Scope split: Task 1 has been split into 1a (data-shape plumbing — additive, compiles standalone) and 1b (handler wiring — adds calls into the new shapes). An intermediate `cargo build --lib` checkpoint after 1a ensures no half-applied state. Task 2 then rewires lib.rs and IPC against the new shapes.
</objective>

## Phase Goal

**As a** AutoMux user, **I want to** make changes to my macros and close the app without ever clicking Save, **so that** when I reopen AutoMux every change I made — added macros, renamed targets, edited sequences, toggled enabled flags — is exactly as I left it.
