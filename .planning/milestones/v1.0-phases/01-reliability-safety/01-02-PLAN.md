<objective>
Deliver the macOS half of Phase 1's platform reliability slice: eliminate the macOS injection-path panic (SAFE-01 site 1 of 5, D-08) AND make the CGEventTap survive OS-issued timeouts during long sessions (RELY-02, D-09).

Purpose: A user running AutoMux for 30+ minutes today silently loses hotkey response when macOS disables a slow tap callback. A user whose first injection coincides with a CGEventSource failure crashes the entire app. These are paired macOS-platform-layer fixes; both live in platform/macos/ and share a single executor context.

Output: macos/input.rs source() returns Option<CGEventSource> and every caller guards with a let-Some early-return; the CGEventTap closure detects CGEventType::TapDisabledByTimeout (and TapDisabledByUserInput) and calls tap_proxy.enable() inline before any other branch.
</objective>

## Phase Goal

**As a** macOS AutoMux user, **I want to** keep my hotkeys working through long sessions and never have the app crash mid-macro, **so that** a 30-minute AFK session continues responding to my hotkey and a transient CGEvent construction failure becomes a dropped action instead of a process exit.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS kernel → app (CGEventTap callback) | OS delivers untrusted event_type values, including the TapDisabledByTimeout and TapDisabledByUserInput variants. Callback must not panic or block. |
| OS kernel → app (CGEventSource creation) | Construction can fail under resource pressure. Must degrade gracefully. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Denial of Service | MacInputProvider injection hot path | mitigate | SAFE-01 / D-08: replace `.expect()` on `CGEventSource::new(...)` with `.ok()` and guard each caller with a let-Some early return so a transient construction failure drops one action instead of terminating the process |
| T-01-04 | Denial of Service | CGEventTap observer callback | mitigate | RELY-02 / D-09: detect `CGEventType::TapDisabledByTimeout | CGEventType::TapDisabledByUserInput` (the named variants `kCGEventTapDisabledByTimeout`/`kCGEventTapDisabledByUserInput` map to) as the FIRST statement in the callback and call `tap_proxy.enable()` so hotkeys cannot be silently disabled by an OS-issued timeout during long sessions |
| T-01-05 | Tampering | CGEventTap callback (event return value) | accept | Returning `None` from the tap-disabled branch is consistent with the existing ListenOnly tap behaviour; no new event is synthesised, no event is suppressed that would otherwise reach userspace |
</threat_model>
