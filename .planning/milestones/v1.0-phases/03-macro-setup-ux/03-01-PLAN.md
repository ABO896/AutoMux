    2. `CGKEYCODE_TO_NAME: Record<number, string>` — maps CGKeyCode integers to human-readable display names (e.g., 0 → "A", 49 → "Space"). Values verbatim from RESEARCH.md.
    3. `DOM_KEYCODE_TO_VK: Record<string, number>` — maps KeyboardEvent.code strings to Windows VK codes (e.g. `{"KeyA": 65, "Space": 32}`). Keyed by e.code string for consistency with DOM_KEYCODE_TO_CGKEYCODE. Values verbatim from RESEARCH.md "Windows VK Lookup Table" section.
    4. `VK_TO_NAME: Record<number, string>` — maps Windows VK codes to display names. Values verbatim from RESEARCH.md.

    Platform detection at module scope (synchronous, no import needed):
      const IS_MACOS = navigator.platform.toLowerCase().includes("mac");

    Export two functions:
    - `export function domKeycodeToNative(code: string): number` — accepts `e.code` string (e.g. "KeyA", "Space", "F5"), looks up in DOM_KEYCODE_TO_CGKEYCODE (macOS) or DOM_KEYCODE_TO_VK (Windows). Returns 0 if no entry found. All call sites must pass `e.code`, not `e.keyCode`.
    - `export function resolveKeyName(nativeCode: number): string` — looks up in CGKEYCODE_TO_NAME (macOS) or VK_TO_NAME (Windows). Returns `"Key ${nativeCode}"` as fallback per D-03 and UI-SPEC copywriting contract.

    Do NOT export the four lookup tables directly — they are module-private implementation details. Only export the two resolver functions.

    TypeScript strict mode: no implicit any, no unused variables (the four const objects are used by the two functions so they are not unused).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend → IPC | All invoke() calls originate from the Tauri WebView; backend treats them as untrusted |
| IPC → StateActor | Intent channel processes inputs from the IPC layer |
| Rust → OS (macOS NSWorkspace) | Reading running apps — read-only, no privilege escalation |
| Rust → OS (Windows EnumWindows) | Enumerating visible windows — read-only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | set_macro_trigger_key IPC | mitigate | Uuid comes from frontend; StateActor silently ignores unknown IDs via `get_mut` returning None — no mutation on invalid ID, consistent with SetMacroTargetApp pattern |
| T-03-02 | Information Disclosure | list_running_apps macOS | accept | Returns app display names and bundle IDs of foreground apps visible to NSWorkspace — same info visible in macOS Dock; no elevated access required, runningApplications does not require Accessibility permission |
| T-03-03 | Information Disclosure | list_running_apps Windows | accept | Returns exe basenames and full paths of visible windows — same info visible in Task Manager; IPC is same-process trust within Tauri; no cross-process privilege escalation |
| T-03-04 | Denial of Service | list_running_apps (repeated calls) | accept | Called on picker focus only (D-06); no server-side rate limiting needed in same-process Tauri model; NSWorkspace and EnumWindows are fast read-only OS calls |
| T-03-05 | Spoofing | keymap.ts platform detection | accept | navigator.platform used for lookup-table selection only — worst case is wrong display name shown; no security boundary crossed; DOM key capture does not execute code from the key value |
</threat_model>
