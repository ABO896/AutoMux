## Phase Goal

**As a** AutoMux maintainer publishing a release,
**I want to** have every third-party GitHub Action in release.yml pinned to a full commit SHA,
**so that** a compromised upstream tag cannot inject malicious build steps into a signed release artifact.

<objective>
Pin the two third-party actions used by the release workflow (`dtolnay/rust-toolchain@stable` and `tauri-apps/tauri-action@v0`) to their full 40-character commit SHAs, while preserving the human-readable tag as an inline comment. GitHub-owned actions are intentionally left on floating tags per D-04.

Purpose: Closes CI-02. Removes the supply-chain risk that a hijacked or moved upstream tag silently changes what runs inside the release job, which has `contents: write` permission and `GITHUB_TOKEN` access.

Output: A modified `.github/workflows/release.yml` whose two third-party `uses:` lines reference full commit SHAs with `# <tag>` annotations.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → third-party action code | Each `uses:` line pulls and executes arbitrary code inside the release job, which has `contents: write` and access to `GITHUB_TOKEN`. The boundary crossed is "trusted CI runtime" → "external repository code." |
| Floating tag → resolved commit | A floating tag (`@stable`, `@v0`) can be force-moved by the upstream maintainer (or by an attacker who compromises the upstream account) to point at malicious commits. Pinning to a commit SHA closes this mutation channel. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `dtolnay/rust-toolchain@stable` floating tag | mitigate | Pin to full 40-char commit SHA (Task 2, replacement 1). Future upgrades require an explicit SHA bump, reviewed in a PR. |
| T-04-02 | Tampering | `tauri-apps/tauri-action@v0` floating tag | mitigate | Pin to full 40-char commit SHA (Task 2, replacement 2). |
| T-04-03 | Elevation of Privilege | Compromised upstream action exfiltrating `GITHUB_TOKEN` from the release job | mitigate | Same SHA pinning as T-04-01/02 — an attacker who moves the floating tag cannot reach the pinned commit. Residual risk: the pinned commit itself being malicious is assumed out of scope (Task 1 resolves SHAs at execution time from the current trusted tag content; reviewers can audit the SHA against the upstream history before merge). |
| T-04-04 | Tampering | `actions/checkout@v4` and `actions/setup-node@v4` floating tags | accept | Per D-04, GitHub-owned actions are trusted and left on floating tags. Rationale: GitHub itself controls these refs; the same trust required to run the workflow at all is required to trust their tag movement. Documented in CONTEXT.md D-04. |
| T-04-05 | Repudiation | SHA resolved at edit time differs from SHA committed | mitigate | Task 1 idempotency check (re-run resolution and confirm match) plus the verification grep in Task 2 ensure the committed SHA is the one actually resolved. |
</threat_model>
