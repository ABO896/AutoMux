<objective>
Add the data model for modifier-aware hotkeys and derived conflict tracking, and convert the platform trigger-key registries to `(keycode, modifiers)` keys. Also pin the platform-specific modifier bit constants with assertions so the frontend/backend bit values cannot drift.

Purpose: This plan lays the foundation for UX-11 (conflict detection) and UX-13 (broader key range) by giving the state model the fields it needs. No business logic changes — only the data shape and the lookup keys. The next plan (08-02) builds the conflict detection on top of these fields.

Output: Modified `state/mod.rs` (new fields + `InputConflict` struct), modified `platform/macos/observer.rs` and `platform/windows/mod.rs` (type change for `MACRO_TRIGGER_KEYS`), and inline unit tests pinning the modifier bit constants.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend → IPC | Untrusted DOM input crosses here; IPC handlers parse the raw user keypress into a `u16` keycode and `u64` modifier bitmask |
| StateActor → Platform statics | The StateActor is the single source of truth; platform statics are write-only mirrors |
| Persisted profile (JSON) → AppState | Old profile files lack the new `trigger_modifiers` and `conflicts` fields; the deserializer must accept missing values without failing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|----------------|
| T-08-01 | Tampering | `MacroConfig.trigger_modifiers` | mitigate | `#[serde(default)]` ensures old profiles load as `0` (no modifiers). Doc comment names the platform bit layout so future maintainers do not invent new values. Unit tests in Task 2 pin the constants so the bit definitions cannot drift. |
| T-08-02 | Tampering | `AppState.conflicts` deserialization | mitigate | `#[serde(default)]` allows old profiles to load with `conflicts: []`. The field is derived, not source-of-truth, so missing values are correct on load. |
| T-08-03 | Spoofing | `MACRO_TRIGGER_KEYS` type change | mitigate | The map key now includes `u64` modifier bits, so a frontend that sends `modifiers: 0` cannot collide with a frontend that sends `modifiers: 0x100000` (Cmd) for the same keycode. The two bindings live in separate map slots. |
| T-08-04 | Information Disclosure | Modifier bit constants in doc comment | accept | The bit values are public Apple/Microsoft-documented constants. No security boundary; the values are required for the frontend to send correct bits. |
| T-08-05 | Repudiation | Silent key overwrite in `reevaluate_all_macros` | accept (interim) | Task 3 retains the silent-overwrite behavior in the underlying map. Plan 08-02 introduces the `check_trigger_key_conflict` pre-check that makes the silent overwrite unreachable in normal user flow. The raw `insert` is preserved as a structural invariant — it is the only way to update a `HashMap` entry. |
| T-08-06 | Denial of Service | `recompute_conflicts` O(n²) expansion | accept (n is small) | 08-02 will add the conflict detection; the per-macro cost is bounded by sequence length. A 1000-macro stress test would still complete in microseconds. Not a real DoS vector. |
| T-08-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies in this phase. All work is in-tree. slopcheck gate not relevant since no installs. |
</threat_model>
