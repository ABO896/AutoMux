## Interaction Notes

### Polling — extended 3-second loop (COMPAT-04)

The existing 3s `setInterval` in App.tsx (lines 169–182) that calls `check_accessibility` is **extended** to also call `check_input_monitoring`. The single `createEffect` continues to handle both. No new polling effect is created.

```tsx
// Conceptual shape — extends existing effect:
createEffect(() => {
  const interval = setInterval(async () => {
    try {
      const [a11y, im] = await Promise.all([
        invoke<boolean>("check_accessibility"),
        invoke<boolean>("check_input_monitoring"),
      ]);
      setAccessibility(a11y);
      setInputMonitoring(im);
      clearPending();
    } catch (_) { /* ignore */ }
  }, 3000);
  onCleanup(() => clearInterval(interval));
});
```

### Input Monitoring — soft warning, not hard block (D-06)

The Input Monitoring row displays the **"Warning"** status label (not "Denied") when its probe returns false. The status dot is the danger color but the label text uses a softer verb. Rationale: per D-06, mouse macros still work without Input Monitoring — only global hotkey activation is affected. The label must communicate this so the user does not think the engine is broken.

The "Grant Access" button on the Input Monitoring row is rendered with the same styling as Accessibility's "Grant Access" button — same accent-tinted ghost button, same `bg-accent/10 border border-accent/30 text-accent`. Clicking it opens `x-apple.systempreferences:com.apple.preference.security?Privacy_ListenEvent` via `@tauri-apps/plugin-opener`'s `open()` function (not a custom `invoke("open_url")` call).

### TCC identity change copy (COMPAT-05)

When the backend `was_ever_granted` flag exists **and** Accessibility is denied, the Accessibility row's subtitle changes from the default copy to the identity-change copy. The status dot stays red (Denied), the "Grant Access" button stays visible with the same flow. **Only the subtitle text changes.**

The Input Monitoring row's subtitle does not change in the identity-change scenario — both permissions are revoked together by TCC, but the user-actionable copy targets Accessibility because that is the primary blocker for input injection. (Input Monitoring denial already shows the "Hotkeys will not fire" subtitle by default.)

### Input Monitoring subtitle copy — state matrix

| Accessibility | Input Monitoring | Input Monitoring subtitle |
|---------------|------------------|---------------------------|
| granted (or pending) | granted | "Required for global hotkeys" |
| granted (or pending) | denied | "Required for global hotkeys" *(still primary copy — Accessibility-implies-InputMonitoring; the warning is communicated by the dot color and "Warning" status label)* |
| denied | granted | "Required for global hotkeys" |
| denied | denied | "Hotkeys will not fire. Mouse macros still work." |

The third row is the most common case for users with a TCC identity change. The fourth row is the most common case for fresh installs.

### Auto-save error banner — listener lifecycle (ERR-01)

The `listen('auto-save-error', ...)` subscription follows the existing `state-changed` listener pattern (`App.tsx:158–166`):

```tsx
createEffect(() => {
  const unlisten = listen<string>("auto-save-error", (_event) => {
    // Show banner; do not surface event payload string (D-13)
    setSaveError(true);
  });
  onCleanup(() => { unlisten.then((fn) => fn()); });
});
```

- Signal type: `createSignal<boolean>(false)` (presence-only; no message body)
- Banner content is the fixed copy in the contract above — never reads the event payload
- `onCleanup` ensures listener removal on component unmount / HMR remount

### Grant button — visual feedback

Clicking either "Grant Access" button:
1. Opens the appropriate System Settings pane via `@tauri-apps/plugin-opener`'s `open()` (no separate `invoke("open_url")` call)
2. Sets the relevant `*Pending` signal to `true` (status row immediately shows "Pending…" with warning pulse)
3. Polling loop (3s) detects the grant on next tick and clears the pending state

This pattern is identical to the existing Accessibility flow (`App.tsx:208–226` `handleRequestAccess`); the Input Monitoring handler is a new sibling function `handleRequestInputMonitoringAccess` with the same structure but a different URL constant.

## State Changes

### New signals

| Signal | Type | Initial | Purpose |
|--------|------|---------|---------|
| `inputMonitoring` | `boolean \| null` | `null` | Mirrors `accessibility` — Input Monitoring probe result |

| `tccIdentityChanged` | `boolean` | `false` | Set true at startup when `was_ever_granted` flag exists AND any permission is denied |

| Effect | Purpose |
|--------|---------|

| Initial-fetch `createEffect` (extended) | `Promise.all` now also fetches `check_input_monitoring` and `tcc_identity_changed` (new IPC command) |

| `get_tcc_identity_status` | none | `boolean` | New `#[command]` — returns `true` if `was_ever_granted` flag file exists at startup |

## Accessibility Notes

- **Color is not the only signal.** Status uses dot color + text label ("Granted" / "Denied" / "Pending…" / "Warning"). The label is always present; the dot is decorative.
- **Status pulse animation** (`pulse-glow` 2s infinite) draws attention to Denied and Pending states. Respects `prefers-reduced-motion` via existing keyframe — no new motion is added in this phase.
- **Focus ring on Grant Access button:** inherited from the existing button styling pattern (`transition-all duration-200` on hover). The new buttons match the existing focus behavior.
- **Dismiss button** on the auto-save error banner is a real `<button>` element with text content "Dismiss" (not an icon-only button). Keyboard-accessible by default.
- **Tauri drag region:** unchanged. Banner is inside the scrollable content area, not the title bar, so no drag-region conflict.
