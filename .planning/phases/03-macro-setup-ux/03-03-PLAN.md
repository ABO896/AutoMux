<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend → IPC (picker) | invoke("list_running_apps") returns OS data displayed in <select> options |
| User selection → IPC (card edit) | Selected option value becomes target_app stored in MacroConfig |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Information Disclosure | list_running_apps display in picker | accept | Options display bundle IDs / exe paths of user's own running apps — same info visible in macOS Activity Monitor / Windows Task Manager; no additional disclosure beyond what OS already exposes to the local user |
| T-03-11 | Tampering | Picker onChange target_app value | mitigate | Value written to newMacroTarget signal comes from a <select> whose options are populated from the IPC response — no free-form text entry; backend set_macro_target_app accepts any string but the Intent channel + StateActor enforces it as a pure field update with no code execution |
| T-03-12 | Denial of Service | handlePickerFocus called on every focus | mitigate | Guard `if (appsLoading()) return;` at the top of handlePickerFocus prevents a duplicate in-flight IPC call when both the card onClick and the select's onFocus fire on the same interaction; each new picker open correctly re-fetches per D-06 |
| T-03-13 | Elevation of Privilege | handleCardSetTargetApp with empty string | mitigate | `targetApp || null` converts empty string to null before sending to IPC, consistent with existing set_macro_target_app null-clear pattern; StateActor sets target_app = None, which means Global targeting (no restriction) — intended behavior |
</threat_model>
