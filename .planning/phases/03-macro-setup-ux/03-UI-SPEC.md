## Component Inventory

### 1. Key Capture Widget

Replaces `<input type="number" id="input-macro-trigger-key">` (line 515–523 in App.tsx).

**States:**

| State | Visual Treatment |
|-------|-----------------|
| Idle (no key set) | `bg-background border border-border rounded-lg px-3 py-2 text-sm text-text-dim` — displays placeholder "Click to set key…" |
| Idle (key set) | Same container; displays key name in `text-text-main` (e.g., "Space", "F5", "Left Shift") |
| Recording | Border changes to `border-accent` full opacity; glow `shadow-[0_0_8px_var(--color-accent-glow)]`; placeholder changes to "Press a key…" in `text-accent`; no other animation required |
| Cancel affordance | A small "✕" button appears inside the field trailing edge while in recording state; `text-text-dim hover:text-text-main`; clicking it exits recording without committing |

**Interaction flow:**
1. User clicks the widget → enters recording state (attach `keydown` listener to `document`).
2. User presses any key → `keydown.code` / `keydown.keyCode` captured; lookup table resolves name; recording state exits; name displayed; integer stored in signal.
3. User clicks ✕ or presses Escape → recording exits; previous value (or empty) restored.
4. `keydown` listener must call `e.preventDefault()` and `e.stopPropagation()` to prevent the captured key from acting on the app.
5. Listener is registered on entry and removed on exit or `onCleanup`.

**Key name display rules:**
- If keyCode is in the lookup table → display the mapped name (e.g., `32 → "Space"`, `65 → "A"`, `116 → "F5"`).
- If keyCode has no entry → display `"Key {N}"` as fallback (e.g., `"Key 179"`). Do NOT show raw integers without the "Key " prefix.
- After capture, the integer keyCode is stored in `trigger_key: number | null` on the config. The name is display-only in the frontend lookup table (D-03).

**Creation form placement:** Replaces the `<input type="number">` in the flex row with the trigger mode `<select>`. Width matches the original `w-40` constraint.

**Macro card placement (D-07, D-08):** The existing key badge `<span class="px-1.5 py-0.5 rounded bg-surface-alt border border-border text-[10px] font-mono">Key {N}</span>` becomes clickable. On click it enters recording mode inline. After capture it calls `bind_hotkey` IPC and auto-commits. A cursor affordance (`cursor-pointer`) and hover border `hover:border-accent/40` signal editability.

### 2. Process Picker Widget

Replaces `<input type="text" id="input-macro-target">` (lines 493–501 in App.tsx).

**Rendered as:** `<select>` element — same element type and Tailwind classes as the existing input-type selector (lines 472–482) and trigger mode selector (lines 505–514).

**Class string (matches existing `<select>` pattern exactly):**
```
bg-background border border-border rounded-lg px-3 py-2 text-sm
focus:outline-none focus:border-accent/50 transition-colors text-text-main cursor-pointer
```
Apply `w-full` in the creation form (replacing the full-width `<input>`). Apply `flex-1` or appropriate sizing on macro card.

**Option format:**
- First option (sentinel): `<option value="">🌐 Global (no target)</option>` — value is empty string, which maps to `null` in the model.
- Subsequent options: `<option value="{identifier}">{display name} ({identifier})</option>`
  - macOS example: `<option value="com.mojang.minecraft">Minecraft (com.mojang.minecraft)</option>`
  - Windows example: `<option value="C:\...\Minecraft.exe">Minecraft (C:\...\Minecraft.exe)</option>`

**Loading state:** While `list_running_apps` is in-flight, show a single disabled option: `<option disabled>Loading…</option>`. Replace with results on resolve.

**Error state:** If `list_running_apps` throws, show a single disabled option: `<option disabled>Failed to load apps</option>`. The select remains visible but non-functional; existing `target_app` value is preserved.

**Fetch trigger (D-06):** Call `list_running_apps` on `onFocus` of the `<select>` element, wrapping in a `createEffect`-style `async` handler. Use `onCleanup` to cancel if component unmounts mid-fetch.

**Macro card placement (D-07, D-08):** The existing target display `<span class="font-mono">{macro.target_app || "Global"}</span>` becomes clickable. On click it renders an inline `<select>` (same classes as above, sized to content). Selecting an option calls `set_macro_target_app` IPC and auto-commits; the select then collapses back to display text. Pressing Escape collapses without committing.

## Platform-Conditional Behaviour

| Behaviour | macOS | Windows |
|-----------|-------|---------|
| Key capture stores | CGKeyCode integer (from `e.keyCode`) | Windows VK code integer (from `e.keyCode`) |
| Key capture commit path | `bind_hotkey` IPC (existing, macOS-only) for card edit; `newMacroTriggerKey` signal for creation form | `newMacroTriggerKey` signal only (no `bind_hotkey` on Windows per D-08 + CONTEXT.md deferred list) |
| Process picker lists | Bundle IDs (e.g., `com.mojang.minecraft`) via new `list_running_apps` IPC (macOS impl) | Exe paths (e.g., `C:\...\app.exe`) via new `list_running_apps` IPC (Windows impl) |
| Process picker stored value | Bundle ID string | Exe path string |

These are backend concerns but govern what the picker displays; the frontend widget is identical on both platforms.
