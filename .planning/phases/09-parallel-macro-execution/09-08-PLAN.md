<task type="auto">
  <name>Task 1: Add a delete control to each macro card (G-09-1b)</name>
  <files>src/App.tsx</files>
  <action>
Add an async handler near `handleToggleMacro` (App.tsx ~line 511):

    async function handleRemoveMacro(id: string, name: string) {
      if (!window.confirm(`Delete macro "${name}"?`)) return;
      try {
        await invoke("remove_macro", { id });
      } catch (e) {
        console.error("Remove macro failed:", e);
      }
    }

Rationale for the pieces:
  - `window.confirm` is a lightweight guard against accidental, unrecoverable deletion. The dashboard tab has no modal/toast helper (only the profiles tab has `showProfileMsg`), and Phase 10 owns the full redesign — the native confirm is the minimal consistent interim choice.
  - The IPC arg name is `id` (the backend command signature is `remove_macro(state, id: Uuid)`); pass `{ id }`.
  - The try/catch + `console.error` mirrors `handleToggleMacro`'s error handling.
  - Do NOT add a manual state refresh: the backend `Intent::RemoveMacro` runs `auto_save_default` and the StateActor broadcasts the new AppState, so the existing `state-changed` listener (App.tsx:333-334) drops the card automatically — identical to how `handleToggleMacro` relies on the broadcast.

Wire a delete button into the macro card header. The header row is the `<div class="flex items-center justify-between mb-2">` at ~line 1243; its right-hand side currently holds only the enable/disable toggle (`<div class="toggle-track" ...>` at ~line 1273). Wrap the toggle and a new delete button together in a `<div class="flex items-center gap-1.5">` so they do not overlap, and add:

    <button
      onClick={() => handleRemoveMacro(macro.id, macro.name)}
      class="px-2.5 py-1 rounded-md text-[10px] font-medium transition-colors cursor-pointer
             bg-danger/10 text-danger border border-danger/20 hover:bg-danger/20"
      title="Delete macro"
    >
      ✕
    </button>

This mirrors the existing profile delete button styling (App.tsx:1539-1547). This is the missing frontend call site for the already-wired backend `remove_macro`.
