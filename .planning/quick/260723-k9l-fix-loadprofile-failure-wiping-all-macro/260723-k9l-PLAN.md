<objective>
Fix the LoadProfile data-loss blocker: a single failed "Load Profile" click currently destroys every configured macro, in memory AND on disk. The `Intent::LoadProfile` handler clears `state.macros` and stops all scheduler tasks BEFORE reading the profile from disk, then unconditionally auto-saves the emptied state to `default.json`. If `load_profile()` returns `Err` (missing file, corrupt JSON, I/O error) the macros are never restored and the empty state is persisted — permanent data loss.

Apply the pre-approved fix (reorder the handler so destructive mutation + auto-save run only on a successful load; the Err branch restarts scheduler tasks and does NOT persist), add a regression test at the persistence layer proving a failed load cannot wipe a saved profile, and close out the backlog todo.

Purpose: Protect the user's configured macros — the app's core value ("a macro that was set up must fire reliably") depends on the durable macro store surviving a failed profile load.
Output: Patched handler in `state/mod.rs`, a `#[tokio::test]` regression test in `persistence.rs`, and the backlog todo moved to `completed/`.
</objective>

   - `Err(e)`: run, in this order — `self.reevaluate_all_macros().await;` (REQUIRED — this restarts the scheduler tasks that the unconditional StopAll just tore down for the still-current, untouched `self.state.macros`; without it a failed load silently stops every running macro); then `self.state.loading_profile = false;`; then `use tauri::Emitter;` + `let _ = self.app_handle.emit("auto-save-error", e.to_string());`; then `let _ = reply.send(Err(e));`. 5. Preserve the existing WR-02 rationale comment (the outer `run()` loop already broadcasts after every `handle_intent`, so do not add a `broadcast_state()` call here).

Net effect: on failure, `state.macros` and `default.json` are untouched; on success, behavior is identical to today.
